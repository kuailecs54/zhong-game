## Context

游戏的过程名称此前对齐《系统集成项目管理工程师教程·第3版》："制订项目管理计划""制订进度计划"用"制订"，整合管理含"管理项目知识"。备考目标切换为《信息系统项目管理师教程（第4版）》后，第四版对计划类过程统一使用"制定"，并把过程"实施风险应对"写作"实施风险应对措施"。数据全部来自 `public/data/*.json`，UI 渲染不硬编码术语，因此改动集中在数据层与少量注释/文档。

经核对多个第四版备考资料，第四版 49 过程矩阵分布为 启动2、规划24、执行10、监控12、收尾1（整合 7 含"管理项目知识"、进度 6、资源 6）——与游戏当前数据结构完全一致，无需调整过程组/知识领域的归属。

## Goals / Non-Goals

**Goals:**
- 所有过程名称与第四版教材一致，不引入教材之外的词汇
- 保持 49 过程矩阵数量与位置不变，不触碰游戏逻辑与关卡配置

**Non-Goals:**
- 不改动 ITTO 数据（keyed by process id，过程 id 未变，无需动）
- 不改动过程组/知识领域的名称、id、顺序
- 不重排过程的 id、顺序、难度

## Decisions

**D1：计划类过程"制订"→"制定"（p002 制定项目管理计划、p018 制定进度计划）**
理由：用户提供的第四版备考表格与多家第四版备考资料均写作"制定项目管理计划""制定进度计划"。`shortName`（制定计划/制定进度）同步。教材对"制定项目章程""制定预算"本就用"制定"，**保持不变**。

**D2：p041"实施风险应对"→"实施风险应对措施"**
理由：第四版备考表格过程名为"实施风险应对措施"。`shortName`（实施应对）不含被改词，保持不变。

**D3：保留游戏数据结构，不删除"管理项目知识"、不移入"估算活动资源"**
理由：用户表格把"估算活动资源"同时列入进度管理与资源管理（同一过程重复计数），但第四版实际矩阵中"估算活动资源"只在资源管理，整合管理含"管理项目知识"（7 个）。经与用户确认，保留现结构（整合 7/进度 6/资源 6=49），仅按表格改名称。

**D4：不新增任何数据字段或词表**
理由：改动仅限既有字符串替换，不需要引入术语映射表之类的新机制——最小改动，避免过度设计。

## Risks / Trade-offs

- [存档进度的 UI 提示与过程名无关] → 无风险；`localStorage` 只存进度（分数/星级），不含过程名
- [改了名词可能影响玩家记忆习惯] → 这正是变更目的（对齐第四版），刻意为之
- ["制订/制定"在不同版本教材写法不同] → 本项目已切换备考目标为第四版，严格按第四版统一为"制定"

## Migration Plan

无迁移：纯数据替换，直接改 `public/data/processes.json` 后跑 `npm run build` 验证 `validateProcessMatrix` 通过即可。回滚只需 revert 数据文件。
