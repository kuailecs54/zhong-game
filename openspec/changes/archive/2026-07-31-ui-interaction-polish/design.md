## Context

项目已完成核心玩法开发（49 过程下落归类游戏），具备完整的关卡系统、用户进度、游戏循环、矩阵/列两种布局模式。当前视觉以深色玻璃拟态 + 木质书桌拟物为主，但各页面之间风格不完全统一，动效细腻度和交互手感有提升空间。

技术栈：Vue 3 + TypeScript + Vite + Pinia + vue-router，纯前端，无后端。

## Goals / Non-Goals

**Goals:**
- 提升整体 UI 视觉质感，统一玻璃拟态与木质拟物的融合风格
- 增强游戏内交互手感（捕获、拖拽、放置、反馈）
- 完善 HUD 信息层级与动效反馈
- 优化页面过渡与入场动画
- 提升移动端小屏体验
- 不改变任何游戏逻辑和数据模型

**Non-Goals:**
- 不新增游戏玩法或关卡
- 不修改状态管理逻辑（game store / user store 的数据结构不变）
- 不引入新的第三方动画库（使用原生 CSS + Vue transition 即可）
- 不改动数据加载和校验逻辑

## Decisions

### 1. 风格统一策略：现代玻璃拟态为主，木质拟物点缀

**决策**：保留书桌/书架的木质温暖感，但将边缘柔化（更大圆角、柔光阴影），与玻璃拟态 HUD 过渡更自然。整体以深色玻璃为主基调，木质元素作为游戏区的"舞台道具"存在。

**理由**：完全去掉木质会失去"书本归类到书架"的主题隐喻；完全木质化则与首页/选关/结算页的玻璃风格割裂。折中方案兼顾主题统一与视觉层次。

**备选**：
- 全玻璃现代风：干净但失去游戏主题感
- 全木质书房风：沉浸感强但与现有页面风格差距太大，改造量也大

### 2. 动效实现方式：CSS transition/animation + Vue Transition

**决策**：所有动效使用原生 CSS `transition`、`@keyframes` 和 Vue `<Transition>` 组件实现，不引入 GSAP 等动画库。

**理由**：当前项目无外部动画库依赖，CSS 动画足够覆盖需求（过渡、脉冲、摇晃、弹出等），零依赖，性能好。复杂的跟随动画（如拖拽跟手）已经用 JS 实现。

### 3. 移动端布局策略：响应式 + 渐进式降级

**决策**：桌面端保持现有左右布局（游戏区 + 书架侧栏），移动端（<768px）改为底部抽屉式书架，游戏区占满宽度。

**理由**：手机竖屏宽度有限，侧栏挤压游戏区导致下落空间太小。底部抽屉更符合手机单手操作习惯。

### 4. HUD 信息架构调整

**决策**：保留左右分栏结构，但优化为"左：分数 + 进度条；右：生命 + 连击 + 道具按钮"的组合。进度用进度条可视化，分数加数字滚动效果。

**理由**：当前进度仅显示数字（如 8/20），进度条更直观。分数作为核心数值需要更强的视觉反馈。

### 5. 拖拽反馈增强

**决策**：增加三层拖拽反馈：
1. **起手**：卡片微放大 + 上浮 + 阴影加深
2. **悬停目标**：可放置目标高亮脉冲 + 微放大（磁吸感）
3. **放置**：正确→弹入书架 + 书架微下沉；错误→弧线回弹回书桌 + 摇晃

**理由**：当前拖拽只有位置跟随，缺乏物理感和状态反馈，操作手感偏"飘"。

## Risks / Trade-offs

| 风险 | 缓解措施 |
|------|----------|
| 过多动效导致低端设备掉帧 | 动画使用 `transform` 和 `opacity`（GPU 加速），避免 `top/left` 布局动画；用 `prefers-reduced-motion` 媒体查询支持减少动效模式 |
| 全局样式改动影响其他页面 | 组件样式使用 scoped，全局变量改动需逐项验证；修改后跑 `npm run build` |
| 拖拽改动引入交互 bug | 保持现有拖拽核心逻辑（`onDragStart`/`onDragMove`/`onDragEnd`）不变，仅加 CSS 类和视觉反馈 |
| 移动端改造工作量大 | 优先用 CSS media query 做布局调整，复杂的抽屉交互可作为后续迭代 |
