# 项目管理归类游戏

帮助备考「系统集成项目管理工程师（中级）」的考生记忆 **49 个项目管理过程** 及其在 **5 大过程组 × 10 大知识领域** 矩阵中的位置，通过「下落 + 归类」的游戏化方式强化记忆。

游戏模式为：卡片下落 → 点击捕获 → 放置到对应列/格 → 判分，并包含生命、连击、星级、冰冻道具等玩法要素。

> 数据依据《系统集成项目管理工程师教程（第 3 版）》。

## 功能特性

- **49 个过程全覆盖**：按课本全名收录 49 个过程，运行时校验矩阵分布（5 大过程组 × 10 大知识领域）。
- **两种布局模式**：
  - **列模式（columns）**：按过程组或知识领域分类卡片。
  - **矩阵模式（matrix）**：5 过程组 × N 知识领域的二维矩阵，需同时匹配过程组与知识领域。
- **12 个关卡（4 阶段 × 3 关）**：从「启动 / 收尾」两列入门，逐步过渡到五过程组、十知识领域，直至完整 5×10 矩阵终极挑战。
- **渐进式难度**：下落速度、生成间隔随正确放置数量动态提升，关卡阶段越高干扰项越多。
- **游戏化机制**：
  - **生命值**：正解卡掉地扣生命，生命归零失败。
  - **连击**：连续正确放置提升得分倍率（最高 5 倍）。
  - **星级评定**：依据准确率与剩余生命评定 1-3 星。
  - **冰冻道具**：冻结全场下落卡片 3 秒，为关键判断争取时间。
  - **干扰项**：混入非本关目标的过程卡片，需识别并忽略。
- **关卡解锁**：通关上一关（≥1 星）才能解锁下一关。
- **进度持久化**：用户名与关卡星级/最高分保存在浏览器 `localStorage`（纯前端，无后端）。

## 技术栈

- **Vue 3** + **TypeScript** + **Vite**
- **Pinia**（状态管理：单局游戏逻辑、用户进度）
- **vue-router**（4 条路由：`/`、`/levels`、`/game/:levelId`、`/result/:levelId`）
- **Vitest**（纯函数单元测试）

## 快速开始

```bash
npm install       # 安装依赖
npm run dev       # 开发服务器，默认端口 5173
npm run build     # vue-tsc -b && vite build（类型检查 + 构建）
npm run preview   # 预览构建产物
npm run test      # 运行单元测试
```

> `npm run build` 是唯一静态校验方式（无 lint 脚本），修改数据文件后必须运行以校验矩阵。

## 玩法说明

1. **开始**：进入首页输入用户名，进入关卡选择页。
2. **捕获**：点击下落中的卡片，将其放入底部托盘（托盘有容量上限）。
3. **归类**：点击托盘中的卡片，再点击目标列/格进行放置。
   - 列模式匹配单一维度（过程组或知识领域）；
   - 矩阵模式需同时匹配过程组与知识领域。
4. **判分**：放置正确加分并计入连击，错误扣分并清零连击。
5. **结局**：正确放置达到目标数量即通关；生命耗尽则失败。通关后按星级进入结算页。

## 关卡结构

| 阶段 | 主题 | 布局 | 目标 |
| --- | --- | --- | --- |
| 1 | 过程组入门（两列对比） | columns | 启动/收尾 → 规划/执行 → 三组齐下 |
| 2 | 五过程组 | columns | 建立完整认知 → 识别干扰 → 速度挑战 |
| 3 | 十知识领域 | columns | 五大领域（上）→ 五大领域（下）→ 十项全能 |
| 4 | 过程组 × 知识领域矩阵 | matrix | 矩阵初探 → 矩阵进阶 → 终极挑战 |

## 数据与 49 过程约束

- 所有游戏数据来自 `public/data/*.json`，运行时通过 `fetch('/data/...')` 加载。
- 修改 `processes.json` 或 `levels.json` 前，需对照 `book/系统集成项目管理工程师教程_第3版_完整版.md` 核对：
  - **过程一律使用课本全名**，禁止使用缩写（如「排列顺序」应为「排列活动顺序」）。
  - 过程归属须与课本一致，且满足 `src/data/loader.ts` 中 `validateProcessMatrix` 的校验（总数 49、各知识领域在 5 个过程组中的数量匹配 `EXPECTED_MATRIX`）。
- 改动数据后必须运行 `npm run build` 验证矩阵与类型。
